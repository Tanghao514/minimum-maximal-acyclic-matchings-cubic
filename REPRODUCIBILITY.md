# Reproducibility guide

Commands assume the repository root, CPython 3.11.7, NetworkX 3.1, and the
dependencies in `requirements.txt`. The archived correctness values are exact;
wall-clock timings depend on hardware, OS, interpreter build, background load,
and timer noise.

## New post-submission verification (2 October 2026)

The original endpoint-set and GENREG records remain unavailable. A new
standalone auditor has independently recomputed all 4,681 optima, and fresh
GENREG/geng runs reproduce the complete graph-class collection. These are
dated supplementary runs, with separate source and result directories.

```bash
# Check archived new witnesses, exhaustive-layer counts, mappings and hashes.
python scripts/verify_post_submission.py

# Recompute all optima independently (Python 3.11+ and g++ required).
python scripts/run_endpoint_audit.py --output reproduced/endpoint_audit
```

The standalone audit uses no project solvers, graph library, or theorem lower
bound. Full generator rebuild/rerun commands and methodological limits are in
[verification/README.md](verification/README.md).

### Rerun the protocol

```bash
python scripts/reproduce_full_census.py --phase correctness
python scripts/reproduce_full_census.py --phase all
```

The first command runs the independent definition-level gate used by the
publication runner. The second also times every census layer. Output is written
to `reproduced/solver_bc_full_census/`, leaving publication artifacts intact.

The publication used five whole-layer repetitions for `n <= 12`, three for
orders 14 and 16, alternating solver order. Rerun timings need not equal the
paper, but optimums, candidate counts for deterministic code, and discrepancies
should agree exactly.

## Solver C ablation

- Input: deterministic stratified order-16 sample defined by
  `scripts/run_solver_c_ablation_complete.py`.
- Artifact: `results/ablations/solver_c_ablation_complete.csv`.
- Rows: 100 graphs × 5 variants = 500, each with three raw timing repetitions.
- Random seed: none; the sample is deterministic and contains all four
  zero-defect graphs plus 96 evenly positioned defect-five records.
- Verification: `python scripts/verify_paper_numbers.py`.
- Full rerun: first reproduce the full census in the original result layout,
  then run `python scripts/run_solver_c_ablation_complete.py`.
- Key values: approximately 9.7× without the specialized zero-defect routine,
  approximately 15.2× without the theorem defect budget, and 1,853 to 3,268
  recursion nodes when near-leaf maximality pruning is removed on defect-five
  graphs.

## Structural certificates and equality constructions

```bash
python scripts/verify_structural_certificates.py
python scripts/construct.py --n 16
python scripts/construct.py --n 56
```

The structural checker decomposes `F=G[S]` and `H=G[U]`, classifies `H`
components, builds the incidence graph, and verifies `c <= 2t+1`, `c <= k`,
and `n = 4k + 2(c-t)` together with the parity-sensitive upper bound.

## Regenerate the graph census

Install nauty 2.9.3 separately, then:

```bash
python scripts/generate_census.py --geng /path/to/geng
python scripts/verify_census_counts.py --census-dir reproduced/census
```

At order 16, expect 4,060 records. Generator output labels/order can differ;
compare canonical isomorphism classes, not line numbers, when using another
workflow such as GENREG plus `labelg`.
